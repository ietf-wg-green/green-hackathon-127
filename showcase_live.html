Known gaps

GAP-01 ◌ expected failure (gap confirmed)
test_gap01_interface_a_enms_session_required
Interface (a) not modelled — draft-ietf-green-framework §4.1 requires the Controller to record an active EnMS session before accepting or sending aggregate reports.
Fix: add an enms_session_id field to GreenController and require open_enms_session() to be called before build_aggregate_report().
GAP-02 ◌ expected failure (gap confirmed)
test_gap02_accuracy_degrades_when_device_goes_offline
No device-offline lifecycle — When a device stops pushing telemetry the Controller has no method to mark it offline and revert its accuracy to accuracy-estimated.
Fix: add GreenController.mark_device_offline(node_id) which sets record.live=False and record.latest_telemetry=None, then verify accuracy_class reverts.
GAP-03 ◌ expected failure (gap confirmed)
test_gap03_cose_signature_verified_by_controller
COSE signature not cryptographically verified — draft-madpr-green-provenance-01 requires the Controller to verify the COSE_Sign1 structure, not merely echo the traceability-verified flag set by the device itself.
Fix: add a CryptoVerifier to the Controller that validates the COSE_Sign1 payload using the device's public key before setting traceability-verified.
GAP-04 ◌ expected failure (gap confirmed)
test_gap04_interface_g_direct_device_to_enms
Interface (g) completely absent — draft-ietf-green-framework §4.7 defines a direct device→EnMS path that bypasses the Controller. No simulator, test, or data model covers it.
Fix: add a DirectEnmsSimulator and test that Device A can push energy data directly to the EnMS without routing through the Controller.
GAP-05 ◌ expected failure (gap confirmed)
test_gap05_accuracy_like_parent_propagated
accuracy-like-parent not propagated by controller — draft-ietf-green-power-and-energy-yang-05 defines accuracy-like-parent for sub-components that inherit accuracy from their parent. The controller must resolve this to the parent component's accuracy class before including the sub-component in the aggregate report.
Fix: add resolve_accuracy_like_parent() to GreenController and verify the aggregate report reflects the propagated accuracy class.
GAP-06 ◌ expected failure (gap confirmed)
test_gap06_yang_push_requires_active_subscription
YANG Push subscription lifecycle not tested — RFC 8641 §3.1 requires explicit subscribe/modify/delete calls. Current tests call push_telemetry() directly without a subscription.
Fix: add subscribe_yang_push() / unsubscribe_yang_push() to DeviceSimulator and require an active subscription before push_telemetry() succeeds.
GAP-10 ◌ expected failure (gap confirmed)
test_boundary_incomplete_flag_at_u136
Boundary-completeness flag: The controller does not expose an is_accounting_boundary_complete() flag; boundary incompleteness can only be inferred from metered-by relationships being absent, not from an explicit status field.
Fix: add EnergyAccountingBoundary YANG leaf to controller model.
GAP-11 ◌ expected failure (gap confirmed)
test_interval_energy_in_notification
Interval energy YANG Push: The DeviceSimulator only emits instantaneous power (W) in YANG Push notifications; there is no mechanism to push per-interval energy (Wh) as defined in UC2.13. Power readings are used as a proxy (1 W ≈ 1 Wh/h).
Fix: add interval-energy-received/provided leaves to the YANG Push notification structure and a push_interval_telemetry() method to DeviceSimulator.
GAP-12 ◌ expected failure (gap confirmed)
test_aggregate_report_accounting_basis_topology
Accounting-basis metadata: build_aggregate_report() does not include an accounting-basis field documenting that de-duplication was performed via topology relationships (not by numerical value comparison).
Fix: add accounting-basis: topology/value/unknown to the aggregate report.
